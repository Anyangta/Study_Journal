# Study Journal

여러 로컬 환경(PC A, PC B, Claude Code on the web 등)을 오가며 Claude Code로 작업할 때,
세션의 맥락과 진행 상황을 이어가기 위한 **작업 기억 저장소**입니다.

## 왜 필요한가

Claude Code 세션은 로컬 환경이 바뀌면 이전 대화나 작업 맥락을 알 수 없습니다.
이 저장소에 분야별로 작업 기록을 남겨두면, 다른 로컬에서 이 저장소를 pull 받아
Claude Code에게 관련 기록을 읽게 함으로써 마치 이어서 작업하는 것처럼 재개할 수
있습니다.

## 폴더 구조

```
<폴더>/                                        # 예: ICNGC/
  <폴더>_<파일명>/                              # 예: ICNGC_실험노트/
    <날짜>_<종류>_<제목>_<버전>.md                # 예: 2026-09-04_회의록_킥오프_0.0.1.md
CLAUDE.md                                        # Claude Code용 자동 동작 지침
```

- **폴더**: 최상위 분류(ICNGC, 수학 등). **파일명**: 그 안의 하위 묶음 이름 —
  `<폴더>_<파일명>` 폴더가 됩니다. **종류/제목**: 하위폴더 안 문서 하나를 식별.
- 같은 하위폴더 안에서 종류·제목이 같은 문서를 다시 만들면, 새 파일이 아니라
  같은 파일의 **버전만 올라갑니다** (`0.0.1 → 0.0.2 …`, semver 형식).
- 값에 띄어쓰기가 있으면 자동으로 `_`로 바뀝니다 (예: "적분 공식" → "적분_공식").
- 실제 프로젝트 코드는 이 저장소에 넣지 않습니다. 코드는 각 프로젝트의 저장소에
  남기고, 여기에는 "무엇을 했고, 무엇이 남았는지" 기록만 남깁니다.

## 사용 방법

### 새 항목 만들기

Claude에게 이렇게 요청하세요:

```
폴더로 만들어줘 폴더 : ICNGC 파일명 : 실험노트 종류 : 회의록 제목 : 킥오프
```

그러면 Claude가:
1. 원격 저장소를 pull해서 최신 상태를 받고
2. `ICNGC/` 폴더가 없으면 만들고
3. `ICNGC/ICNGC_실험노트/` 하위폴더가 없으면 만들고
4. 그 안에서 "회의록/킥오프" 조합의 문서가 이미 있는지 확인하고
   - 없으면: `2026-09-04_회의록_킥오프_0.0.1.md`로 새로 만들고
   - 있으면: 버전만 올려서(기본은 patch, `0.0.1 → 0.0.2`) 파일명을 바꾸고 내용을
     갱신합니다
5. commit하고 push합니다.

같은 종류·제목으로 다시 요청하면 새 폴더/새 파일이 아니라 **버전만 올라간 같은
파일**로 갱신됩니다. "이건 기능을 추가한 거야"처럼 크기를 알려주면 minor
(`0.1.0`), "구조가 크게 바뀌었어"처럼 말하면 major(`1.0.0`)로 올라갑니다 — 아무
말 없으면 patch만 올라갑니다.

### 새 로컬에서 작업을 이어갈 때

1. 이 저장소를 clone/pull 합니다.
   ```bash
   git clone https://github.com/Anyangta/Study_Journal.git
   # 이미 있다면
   git pull
   ```
2. 이 저장소 안(또는 이 저장소를 참조하며)에서 Claude Code를 실행하면 `CLAUDE.md`를
   자동으로 읽습니다.
3. "ICNGC/실험노트 이어서 할게"처럼 말하면, 해당 폴더의 문서를 읽어 맥락을 파악한
   뒤 이어서 작업합니다.

## 중요: 기본 브랜치는 항상 `main`

**Claude Code on the web에서 새 세션을 열면 세션마다 자동으로 새 브랜치가
생성됩니다.** 그 브랜치에서만 작업하고 push하면, 다른 세션/로컬에서는 그 기록이
보이지 않습니다.

그래서 모든 기록은 결국 **`main` 브랜치**로 모여야 합니다. 세션이 자동으로 다른
브랜치를 잡아줬더라도, 기록을 다 마친 뒤에는 Claude가 그 내용을 `main`에 병합해서
push하도록 되어 있습니다(`CLAUDE.md`의 "브랜치 처리" 절 참고). 만약 GitHub에서
직접 저장소를 확인할 때 최신 기록이 안 보인다면, 주소창의 브랜치가 `main`인지
먼저 확인하세요.

GitHub 저장소 설정(Settings → General → Default branch)에서 기본 브랜치가
`main`으로 지정되어 있어야 합니다.
