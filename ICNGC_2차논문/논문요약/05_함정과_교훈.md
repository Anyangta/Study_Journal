# 걸렸던 함정과 교훈

> 재현하거나 이어받을 사람에게 가장 값어치 있는 부분입니다.
> 다섯 개 다 **결과를 조용히 망가뜨릴 수 있었던** 것들입니다.

## 1. 상태가 압축돼 사라짐

**증상**: 200MB로 설정한 상태가 체크포인트에 **36MB**로 기록됨. 체크포인트 소요가
0.46초밖에 안 나와서 δ가 의미 있는 크기가 안 됨.

**원인**: `new byte[payload]`가 0으로 채워지는데, RocksDB의 블록 압축(Snappy)이
그걸 거의 없애버림.

**해결**: payload를 키 유래 의사난수로 채움. 같은 조건에서 체크포인트가
**534~701MB, 소요 2.1~2.8초**로 정상화.

**교훈**: 합성 워크로드에서 "상태 크기를 설정했다"는 것과 "저장소가 그 크기를
실제로 쓴다"는 건 다른 얘기입니다. 체크포인트 크기를 반드시 확인하세요.

## 2. 계측 도구가 동역학을 못 잡음

**증상**: Flink의 `numRecordsOutPerSecond`와 `records-lag-max`가 250ms 폴링에도
같은 값을 반복하고, 장애 후에도 안 돌아옴.

**원인**: 둘 다 **60초 이동평균**. 체크포인트(2초)나 재시작(4초)의 동역학을
표현할 수 없음.

**해결**: 잡 안에서 서브태스크마다 500ms 주기로 지연 분포를 직접 찍도록 계측을
새로 만듦. Flink REST는 잡 상태와 체크포인트 이벤트에만 사용.

**교훈**: 엔진이 주는 메트릭의 **집계 창**을 먼저 확인하세요. 안 그러면 평평한
선을 보고 "변화가 없다"고 결론 내립니다.

## 3. 정상 구간 추정이 표본을 통째로 날림

**증상**: 장애 런에서 정상 지연이 이상하게 나옴.

**원인**: 장애 후 60초를 일괄 제외했는데 **장애 간격이 55초**라 거의 전 구간이
제외됨.

**해결**: 에피소드별 **실측 복구 시간** 기반 2-패스로 변경 —
1패스에서 20퍼센타일 기준선으로 에피소드를 뽑고, 2패스에서 정제된 정상 수준으로
재계산.

**교훈**: 고정 크기 제외 창은 장애 간격이 그 창보다 짧아지는 순간 조용히
무너집니다.

## 4. 디스크가 실험 조건을 바꿈 (가장 위험했던 것)

**증상**: 무장애 대조군의 지연이 장애를 넣은 런보다 **높게** 나옴 — 말이 안 되는
결과. 정상 지연 적합의 R²가 0.95에서 0.03으로 붕괴.

**원인**: `~/icngc2_stream/rocksdb`에 취소된 잡의 RocksDB 작업 디렉터리가
**65 GB 누적**. 드라이버는 런마다 잡을 취소하지만 Flink는 취소된 잡의 로컬
상태를 정리하지 않음.

| 런 순서 | 체크포인트 소요 | 정상 지연 패턴 |
|---|---|---|
| 초기 (1~7) | 2.1~2.8 s | 깨끗한 1/τ |
| 후기 (29~42) | 4.0~6.6 s | 불규칙 (148~4056 ms) |

**나중 런일수록 느려지는 계통 드리프트**라, 조건 비교가 성립하지 않았습니다.

**해결**: 드라이버가 런마다 로컬 상태를 청소하도록 수정 + 런 종료 시 디스크
사용량을 메타에 기록(재발 감지용). 73 GB 회수 후 전체 재실행. 오염된 42런은
지우지 않고 `results_drift/`에 보존.

**교훈 둘**:
- 장시간 스윕에서는 **엔진이 정리하지 않는 상태 디렉터리**가 조용히 실험 조건을
  바꿉니다. 런마다 크기를 기록해 두세요.
- **말이 안 되는 결과가 나왔기 때문에 잡을 수 있었습니다.** 교차 검증용 대조군
  (무장애 런)을 넣어둔 게 결정적이었습니다. 없었으면 이대로 논문에 실렸을 겁니다.

## 5. 목적함수를 잘못 적분해서 계통 2배 오차

**증상**: 모델 곡선이 실측점보다 일관되게 2배 낮음.

**원인**: 백로그를 시간으로 적분했는데, 실제로 재는 건 **레코드 가중 평균 지연**.
catch-up 동안 레코드는 λ가 아니라 μ_d로 처리되므로, 레코드 가중 합은 백로그
시간적분의 **μ_d/λ 배**입니다.

**확인**: 관측된 배율 1.99가 측정된 μ_d/λ = 1.79와 맞아떨어짐.

**해결**: 목적함수를 레코드 가중 형태로 다시 유도. 최적 조건이
`δ²M = ρτ²(2τ/3+D)` 에서 `δ²M(1−ρ_d)/(1−ρ) = τ²(2τ/3+D)` 로 바뀌고,
ρ가 거의 상쇄됨.

**교훈**: "무엇을 적분하는가"와 "무엇을 측정하는가"가 같은지 확인하세요.
2배는 우연히 맞아떨어지기 쉬운 크기라, 안 잡고 넘어가기 좋습니다.

## 부수적으로 걸렸던 작은 것들

| 함정 | 해결 |
|---|---|
| `EventGen`이 slf4j 없음으로 죽음 | 클래스패스에 `kafka_2.13-3.9.2/libs/*` 전체를 넣어야 함 (`kafka-clients` 단독 불가) |
| 백그라운드 실행이 호출자를 블로킹 | `setsid nohup ... < /dev/null &` — ssh 파이프를 물면 안 됨 |
| `pgrep -f calib.py`가 **자기 자신을 매칭**해 대기 루프 데드락 | `pgrep -f "[c]alib.py"` |
| 잡 파라미터가 TaskManager에 전달 안 됨 | `JVM_ARGS="-Dxxx=..."`로 `flink run`에 전달 (main()이 클라이언트 JVM에서 돌기 때문) |
| payload 4KB에서 μ가 513/s로 붕괴 | 쓰기 대역이 μ×payload로 터짐. 상태는 **키 개수**로 늘릴 것 |
| 스케일링 지수 과장 | 세제곱근은 점근값. 측정 범위 지수는 0.43~0.35 — 그대로 써야 함 |
