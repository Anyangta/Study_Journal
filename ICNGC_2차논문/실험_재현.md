# 실험 재현 가이드 — ICNGC 2차 논문 (스트리밍 체크포인트 주기)

이 문서는 미래의 세션(그리고 사용자)이 이 실험을 **그대로 다시 돌리기 위한** 정보만
담습니다. 결과 해석은 `체크포인트_주기.md`, 논문 문장은 `paper_draft_en.md`.

## 1. 서버 접속

```bash
ssh -p 5409 wontak@220.149.241.201     # cluster04 = 172.29.54.9, 사이트 A
ssh -p 5408 wontak@220.149.241.201     # cluster03 = 172.29.54.8 — 응답 없음
```

- 새 로컬에서는 키 등록이 필요합니다: `ssh-keygen -t ed25519` 후
  `ssh-copy-id -p 5409 wontak@220.149.241.201`.
- **cluster03 상태(2026-09-06 확인)**: ping은 정상(RTT 0.14ms)이고 TCP 핸드셰이크도
  되지만 sshd·MinIO(9000)·에이전트(8800) 어느 것도 응답하지 않음. 커널만 살아있고
  유저스페이스 전체가 멈춘 상태라 **원격 복구 불가, 물리 재부팅 필요**.
- cluster04에서 `sudo`는 비밀번호를 요구하고 docker 소켓도 접근 불가.
  그래서 모든 구성이 홈 디렉터리 사용자 프로세스입니다 (OS 무변경).

## 3. 처음부터 다시 세우기

```bash
cd ~/icngc2_stream
./cluster.sh kafka-start          # KRaft 브로커
./cluster.sh topic-reset 8        # events 토픽 8파티션
./cluster.sh flink-start 3        # JM 1 + TM 3 (슬롯 6)
./cluster.sh status

# 컴파일 (maven 없음 — Flink lib 대상 javac)
javac -nowarn -cp "flink-1.20.5/lib/*" -d classes CkptJob.java && jar cf ckptjob.jar -C classes .
javac -nowarn -cp "lib/kafka-clients-3.9.1.jar" -d gclasses EventGen.java && jar cf eventgen.jar -C gclasses .
```

**주의 (실제로 걸렸던 함정)**

1. `EventGen`은 `kafka_2.13-3.9.2/libs/*` 전체를 클래스패스에 넣어야 합니다
   (`kafka-clients` 단독이면 slf4j 없음으로 죽음).
2. 잡 파라미터는 `JVM_ARGS="-Dxxx=..."` 로 `flink run`에 전달합니다
   (main()이 클라이언트 JVM에서 돌기 때문).
3. `flink-connector-kafka` + `kafka-clients` jar는 `flink-1.20.5/lib/`에 넣어야
   TaskManager에서도 보입니다.
4. 백그라운드 실행은 반드시 `setsid nohup ... < /dev/null &`. ssh 파이프를 물면
   호출자가 블로킹됩니다.
5. `pgrep -f calib.py` 같은 패턴은 **자기 자신을 매칭**합니다. `pgrep -f "[c]alib.py"`.

## 4. 실험 실행

```bash
python3 calib.py conf/calib4.json results/calib4.json     # μ 측정
python3 mkcfg.py conf/spec_m2.json conf/m2.json           # 스윕 설정 생성
./launch.sh conf/m2.json m2                               # detached 실행
tail -f logs/m2.log
```

- `sweep.py`는 `logs/<tag>.log.done`에 완료 런을 기록하므로 **중단 후 같은 명령으로
  재개**하면 남은 런만 돕니다.
- 런 1회 ≈ warmup 75s + measure 480s + 정리 55s ≈ 9.5분.

## 5. 분석

```bash
python3 analyze.py            # results/summary.json, summary.csv

```

## 6. 고정된 실험 파라미터 (바꾸면 결과가 안 맞음)

| 항목 | 값 | 이유 |
|---|---|---|
| spin | 32000 | μ를 ≈110k rec/s로 고정. spin=0이면 μ=1.1M/s라 생성기가 병목 |
| payload | 1024 B, 키 유래 의사난수 | 0으로 채우면 RocksDB 압축에 먹혀 상태 크기가 안 나옴 |
| 상태 크기 | 키 개수로 조절 (100k~800k) | payload로 키우면 쓰기 대역(μ×payload)이 터져 μ가 붕괴 |
| par | 4 (슬롯 6 중) | 장애 후 즉시 재시작할 여유 슬롯 확보 |
| heartbeat.timeout | 5000 ms | 감지 시간 상수 |
| 코어 고정 | Kafka 0-3 / JM 4 / TM 5-12 / gen 13-15 | 공용 서버라 간섭 격리 |
| 계측 | 잡 내부 500ms 지연 요약 | Flink 메트릭은 60초 이동평균이라 사용 불가 |
