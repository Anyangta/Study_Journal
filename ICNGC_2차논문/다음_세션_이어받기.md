## 2. 분석은 한 줄입니다

```bash
ssh icngc-a 'cd ~/icngc2_stream && ./refresh.sh'
```

`analyze.py → drift.py → model.py → verify.py → plot.py`를 **올바른 순서로**
돌립니다. 순서를 틀리면 이전 스윕의 답이 조용히 나오기 때문에 스크립트로
묶어뒀습니다.

### 출력에서 볼 것 (순서대로)

1. **`drift.py controls`** — 대조런들의 산포.
   **여기부터 보세요.** 산포가 크면(1.5배 이상) 그 스윕은 장비가 흔들리는 동안
   측정된 것이고, 그 뒤 숫자를 그대로 믿으면 안 됩니다.
2. **`drift.py fit k200k _r50_ _m0_`** — 무장애 런에서 나온 δ와 R².
   **R²가 0.9 이상이면 δ는 신뢰할 수 있습니다.**
3. **`model.py`** 진단 줄 — `src=m0`이어야 정상 항이 무장애 런에서 나온 것입니다.
   `src=all`이면 무장애 런이 3개 미만이라는 뜻입니다.
4. **`verify.py`** — 몇 개 통과했는지.
   **주의: 여기서 FAIL이 많은 건 정상입니다.** `verify.py`는 *오염된 옛 데이터로
   쓴 논문 수치*와 비교하기 때문입니다. 새 측정이 맞고 논문이 틀린 상태입니다.

## 4. 체인이 끊겼을 때

`chain.sh`는 앞 스윕 로그에 `sweep done`이 찍히면 다음을 띄웁니다.
진행이 멈춰 있으면:

```bash
# 무엇이 살아있나
ssh icngc-a 'ps -u wontak -o etimes,args | grep -E "chain\.sh|sweep\.py" | grep -v grep'

# 아무것도 안 돌면 다음 스윕을 직접 띄운다 (이미 끝난 런은 자동으로 건너뜀)
ssh icngc-a 'cd ~/icngc2_stream && ./launch.sh conf/m8.json m8'

# 그리고 그 뒤를 다시 연결
ssh icngc-a 'cd /home/wontak/icngc2_stream && setsid nohup ./chain.sh m8 conf/m9.json m9 > logs/chain_m9.out 2>&1 < /dev/null &'
```

`sweep.py`는 `logs/<tag>.log.done`을 보고 **이미 끝난 런을 건너뜁니다.**
같은 명령을 다시 돌려도 중복 실행되지 않습니다.

### 잡이 엉켰을 때 정리

```bash
ssh icngc-a 'cd ~/icngc2_stream && python3 -c "
import sys; sys.path.insert(0,\".\")
from driver import stop_gen, cancel_all, ensure_tms
stop_gen(); cancel_all(); ensure_tms(3)
print(\"ok\")"'
```

## 5. 이번에 알아낸 것 중 **꼭 기억해야 할 세 가지**

이걸 모르면 같은 실수를 반복합니다.

### (1) 공용 장비는 하루 안에 체크포인트 처리량이 4배 흔들린다

새벽 268 MB/s → 오후 66 MB/s (체크포인트 크기는 그대로).
그래서 **새 스윕은 반드시 `mkcfg_drift.py`로 만드세요** (`mkcfg.py` 아님).
τ 순서를 섞고 대조런을 끼웁니다. 비교가 목적인 스윕이면 `"interleave": true`도.

### (2) δ는 무장애(mtbf=0) 런에서만 잴 수 있다

M=55 s에서는 정상 구간 표본이 남지 않습니다.
`model.py`가 이제 자동으로 무장애 런을 우선하지만, **새 arm을 만들 때 무장애
블록을 같이 넣는 것**은 사람이 해야 합니다.

### (3) 창 안에 체크포인트가 5개 미만인 런은 버린다

τ=128 s, measure 300 s 런은 체크포인트 3개, sd가 평균의 2.6배, 최대 22초 —
이 한 점이 적합의 부호를 뒤집었습니다. 긴 τ를 재려면 `measure_s`를 늘리세요.
