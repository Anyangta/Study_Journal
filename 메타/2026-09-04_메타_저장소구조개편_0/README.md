## 한 일

- 처음에는 `journal/`(날짜별 세션 기록) 방식으로 저장소를 만들었으나, 사용자 요청에
  따라 **분야별 폴더 체계**로 전면 개편했습니다.
- `journal/` 디렉터리(INDEX.md, 날짜별 기록)를 제거했습니다.
- `CLAUDE.md`에 새 항목 생성 트리거와 절차를 정의했습니다:
  - 트리거: `"폴더로 만들줘 분야:<분야> 제목:<제목>"`
  - 절차: pull → 값 정리(공백/`_` → `-`) → `<분야>/` 폴더 확인/생성 → 같은
    분야 폴더 안에서 같은 제목이 있는지 확인해 버전 계산(없으면 0, 있으면
    최댓값+1) → `<분야>/<날짜>_<분야>_<제목>_<버전>/README.md` 생성 →
    commit/push.
- `templates/entry-template.md`를 새 폴더 구조에 맞게 갱신했습니다.
- `README.md`(사람용 사용법)를 새 구조/명령어 예시로 갱신했습니다.

## 다음 할 일

- 실제로 다른 분야(예: 수학, 알고리즘 등)로 `"폴더로 만들줘 분야:X 제목:Y"`를
  몇 번 실행해서 버전 증가 로직이 의도대로 동작하는지 확인.
- 여러 로컬에서 거의 동시에 같은 분야/제목으로 생성 요청 시 버전이 겹치는 경우의
  충돌 처리(재계산 후 재생성)가 실제로 잘 되는지 확인.

## 참고할 맥락 / 결정 사항

- `journal/`과 분야별 체계를 공존시킬지 고민했으나, 사용자가 "journal/ 없애고
  분야 체계로 통일"을 선택함.
- 항목은 파일이 아니라 **폴더 + 내부 README.md**로 만들기로 결정함 (사용자가
  "폴더로 만들줘"라고 말한 취지를 살리고, 이후 이미지/코드 등 부가 파일을 같이
  넣을 수 있도록).
