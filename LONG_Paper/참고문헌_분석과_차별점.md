## 🔴 위협 1 — Zhuang 2018 (우리 핵심 통찰을 이미 함)

**확인된 내용** (IEEE 초록):
> "Traditional OCI models consider recovery time only related to execution time
> from the last checkpoint to failure, but they are **not suitable for stream
> processing** because recovery time is related to **reprocessing workload, which
> depends on realtime input data.**"

**충격**: 이건 우리 서론 문단 3("배치 모델은 스트리밍에 안 맞다, 되감기가 실시간
입력에 의존한다")과 **거의 같은 주장**입니다. 2018년에 이미 했어요.

**그래서 우리가 못 쓰는 말:**
- ❌ "배치 모델이 스트리밍에 안 맞다는 걸 처음 지적한다"
- ❌ "되감기/재처리가 실시간 입력에 의존함을 처음 밝힌다"

**우리에게 남는 차별점:**
- Zhuang은 **processing efficiency(효율)** 최대화 → OCI를 동적 조정
- 우리는 **record-weighted latency area(지연 면적)** 를 목적함수로 유도
- Zhuang은 "재처리량이 입력에 의존"까지, 우리는 **그 재처리가 backlog 삼각형을
  만들어 비용이 checkpoint age의 quadratic**이라는 기하 구조까지 유도·실측

## 🔴 위협 2 — Jayasekara 2020/2022 (utilization vs 우리 latency)

**확인된 내용** (arXiv/Wiley):
> "Daly minimizes total execution time of **bounded** workload; streaming is
> **unbounded**. We derive optimal interval maximizing **utilization**... optimum
> depends only on checkpoint cost and failure rate. Confirmed on Apache Flink."
> 후속(2022): "utilization뿐 아니라 **latency와 throughput이 어떻게 달라지는지도** 본다."

**충격**: 
- 2020은 목적함수가 **utilization** → 여기가 우리 차별점(우리는 latency)
- **하지만 2022가 latency도 봄** → "기존은 latency 안 봤다"고 쓰면 반박당함

**그래서 우리가 못 쓰는 말:**
- ❌ "기존 OCI 연구는 latency를 보지 않았다" (2022가 봄)

**우리에게 남는 차별점 (중요):**
- Jayasekara는 latency를 **결과 지표(measured outcome)** 로 봄 — utilization을
  최적화한 뒤 "latency가 이렇게 되더라"
- 우리는 latency **자체에서 목적함수를 유도** — record-weighted latency area를
  직접 최소화. **"latency를 본다"가 아니라 "latency로 최적화한다"** 가 차이.

## 🔴 위협 3 — Zhang 2021 (가장 직접 충돌)

**확인된 내용** (Springer):
> "a **performance model to estimate tuples processing latency** and a **recovery
> model to estimate fault recovery time** to obtain optimal checkpoint interval
> under different workload intensities."

**충격**: Zhang은 이미 **(1) 지연 모델 + (2) 복구 모델 → Flink 최적 간격**을 했어요.
**우리가 "Flink에서 지연 고려한 OCI"라고만 하면 완전히 겹칩니다.**

**그래서 우리가 못 쓰는 말:**
- ❌ "Flink에서 지연과 복구를 모델링해 최적 간격을 찾는다" (Zhang이 함)

**우리에게 남는 차별점 (여기가 생명줄):**
- Zhang의 지연 모델은 workload intensity 기반 **tuple latency 추정**
- 우리는 **continuous arrivals → replay backlog → 삼각형 면적 → checkpoint age의
  quadratic**이라는 **수학 구조**를 명시하고, 그걸 **자유 파라미터 없이 R²=0.996으로
  검증**. Zhang은 이 quadratic geometry를 명시하지 않음(원문 확인 필요).
- 우리는 **utilization optimum과 latency optimum의 스케일링 차이**(√M vs M^0.43)를
  대조. 이게 우리만의 프레이밍.

## 🟡 위협 4 — Sebepou 2011 CEC (되감기 novelty 못 씀)

**GPT 설명**: stream operator recovery에서 checkpoint 읽고 log replay로 복구,
checkpoint 드물면 replay량 증가·복구 김.

**그래서 우리가 못 쓰는 말:**
- ❌ "durable log + replay로 복구한다는 관점이 새롭다" (2011에 이미 있음)

**대응**: 되감기 자체는 novelty로 쓰지 말고, **되감기가 만드는 backlog의 정량적
비용 구조**를 novelty로.

## 결론 — 우리 논문의 생존 차별점 (세 겹 방어)

기존 연구를 다 인정하고도 우리에게 남는 것:

1. **목적함수**: record-weighted latency **area를 직접 유도·최적화**
   (Jayasekara=utilization, Zhang=tuple latency 추정 — 우리는 area 기하)
2. **수학 구조**: continuous arrival → replay backlog → **checkpoint age의
   quadratic** → utilization(√M)과 다른 스케일링. 이걸 **자유 파라미터 없이
   R²=0.996으로 검증** (아무도 이 무보정 검증은 안 함)
3. **실무 규칙 + 분산 측정**: δ≈d/2(로컬), 2노드에서 복원 2배 — 구체적 처방

### 서론 차별점 문장 (안전 버전)

> "Stream-specific checkpoint-interval models exist [Zhuang, Jayasekara, Zhang].
> They optimize processing efficiency or utilization, or estimate tuple latency
> empirically. **We differ by deriving the record-weighted latency directly from
> the backlog geometry that continuous arrivals impose on replay-based recovery,
> yielding a cost quadratic in checkpoint age that we validate with no free
> parameter (R²=0.996), and by contrasting the resulting optimum's scaling with
> the utilization optimum.**"
